1. Fast Intro to R

307102 Descriptive Statistics for Business | University of Petra

This is the only part of the course that is about R rather than about statistics. It exists so that everything afterwards can be about statistics.

There are eight things to learn here. That is the whole list. You will not be asked to write loops, define your own functions, or do anything a programmer would recognise as programming. You are learning to operate a tool, not to build one.

Expect this to take about ninety minutes. Do not skip it - every later notebook assumes you have done it.

TipBefore you start

You will make typing mistakes and R will respond with error messages. This happens to everyone, including people who have used R for twenty years.

An error is not a sign that something has gone seriously wrong. It is R saying “I did not understand that”, which is almost always a missing bracket, a missing quote, or a misspelled name. Read the message, check those three things, and try again.

1. R is a calculator that remembers

At its simplest, R is a calculator.

2 + 2
#> [1] 4
150 * 0.05
#> [1] 7.5
(45 + 52 + 38) / 3
#> [1] 45

The [1] in front of each answer is not part of the answer. It is R numbering the output, telling you this line begins with the first result. You will see it constantly. Ignore it.

So far this is Excel with extra steps. What makes R different is the next idea.

2. Objects - giving things names

In Excel a number lives in a cell and you refer to it by address, like B7. Insert a row and B7 becomes something else, and your formulas break.

In R you give a value a name instead. The name never moves.

The arrow <- means “store this under this name”. Read it as “gets”.

tax_rate <- 0.05

item_price <- 120

tax_amount <- item_price * tax_rate

tax_amount
#> [1] 6

Three things worth noticing.

Storing something produces no output. When you ran tax_rate <- 0.05, nothing printed. That is correct - you told R to remember a value, not to show it. To see what is stored, type the name on its own, as the last line does.

Names should say what the thing is. tax_amount is a good name. x is a bad one. In three weeks you will not remember what x was.

Names are case-sensitive and cannot contain spaces. Tax_Rate and tax_rate are different names. Use lowercase with underscores and you will avoid most problems.

Once a value is stored you can reuse it as often as you like:

total_paid <- item_price + tax_amount
total_paid
#> [1] 126

Look at the Environment pane in the top right of RStudio. Every name you have created is listed there. That pane is your R memory - if something is not in it, R does not know about it.

3. Functions - verbs that do things

A function is a command that does something to a value. You have used functions in Excel: SUM, AVERAGE, COUNT. R works the same way with different names.

A function is its name followed by round brackets, with the thing it works on inside.

prices <- c(12.5, 8.0, 45.2, 19.9, 33.1)

mean(prices)
#> [1] 23.74
max(prices)
#> [1] 45.2
length(prices)
#> [1] 5

The c() is itself a function. It stands for “combine” and glues several values into a single list of numbers. In R this is a vector - simply a column of values of the same type.

Some functions take extra instructions, called arguments, separated by commas:

messy_prices <- c(12.5, 8.0, NA, 19.9, 33.1)

mean(messy_prices)
#> [1] NA
mean(messy_prices, na.rm = TRUE)
#> [1] 18.375

NA means “missing value” - a blank cell. The first mean() returns NA because R refuses to guess: if one value is unknown, the true average is unknown too. The argument na.rm = TRUE says “remove the missing values first, then average what is left”.

WarningRemember this one

When a calculation unexpectedly returns NA, missing data is almost always the reason. This causes more confusion later in the course than any other single thing.

NoteSelf-check 1

Without running it, what will length(messy_prices) return - 4 or 5?

NoteShow the answer

5. length() counts how many slots the vector has, and the missing value still occupies a slot. NA means “there is a value here and we do not know it”, not “there is nothing here”.

That distinction matters commercially: a customer who declined to give their age is not the same as a customer who does not exist.

4. Data frames - the spreadsheet inside R

A single vector is one column. Real data has many columns of different types - some numbers, some text, some dates - all lined up so that row 7 in every column refers to the same transaction.

That structure is a data frame. It is the single most important idea in this notebook: a spreadsheet that lives inside R.

Here is a tiny one, built by hand:

library(tidyverse)

branches <- data.frame(
  branch      = c("A", "B", "C"),
  city        = c("Yangon", "Mandalay", "Naypyitaw"),
  staff_count = c(24, 19, 21),
  open_year   = c(2015, 2017, 2016)
)

branches
#>   branch      city staff_count open_year
#> 1      A    Yangon          24      2015
#> 2      B  Mandalay          19      2017
#> 3      C Naypyitaw          21      2016

Three rows, four columns. Each row is one branch. Each column is one piece of information recorded about every branch.

TipThe rule that makes analysis possible

One row per thing, one column per measurement.

Almost everything you do in this course assumes your data is arranged this way. When an analysis will not work, the first thing to check is whether the data actually follows this rule.

The library(tidyverse) line loads the add-on packages you installed during setup. You need one library() call at the start of every session. If you restart R, run it again.

6. The dollar sign - pulling out one column

To work with a single column, write the data frame name, then $, then the column name.

mean(sales$Rating)
#> [1] 6.9727

Read sales$Rating as “the Rating column of sales”.

Because sales$Rating is just a vector of numbers, every function from section 3 works on it:

max(sales$Total)
#> [1] 1042.65
min(sales$Total)
#> [1] 10.6785
length(sales$Total)
#> [1] 1000
WarningColumn names with spaces

When a column name contains a space, R needs help seeing where the name starts and ends. Wrap it in backticks - the key above Tab on most keyboards.

mean(sales$`Unit price`)
#> [1] 55.67213

Without backticks R reads sales$Unit, stops at the space, and cannot find a column called Unit.

This is the single most common error in this course, and now you know the fix.

NoteSelf-check 2

Write one line that finds the average gross income per transaction.

NoteShow the answer 
mean(sales$`gross income`)

Backticks are required because of the space. Note also that this column is spelled in lowercase - gross income, not Gross Income. R is case-sensitive, so capitalisation must match exactly what names(sales) showed you.

7. The pipe - reading code as a sentence

Suppose you want the average transaction value for Branch A only. Written the direct way:

summarise(filter(sales, Branch == "A"), avg = mean(Total))

That works, but it reads inside-out: the first thing that happens (filter) is buried in the middle. With four or five steps it becomes unreadable.

The pipe, written |>, fixes this. It takes whatever is on its left and passes it into the function on its right. It means “and then”.

sales |>
  filter(Branch == "A") |>
  summarise(avg_transaction = mean(Total))
#> # A tibble: 1 × 1
#>   avg_transaction
#>             <dbl>
#> 1            312.

Read that top to bottom as a sentence:

Take the sales data, and then keep only Branch A, and then compute the average of Total.

That is the whole idea. Every analysis in this course is written this way.

Two practical points. Put the pipe at the end of a line, never the start of the next one. And RStudio types it for you with Ctrl+Shift+M (Cmd+Shift+M).

8. The five verbs

Nearly everything you will do to a dataset is one of five operations.

Verb What it does Business question it answers
filter() Keeps some rows “Show me only the credit card sales”
select() Keeps some columns “I only care about branch and total”
arrange() Sorts the rows “Which sale was largest?”
mutate() Adds a new column “What was the margin on each sale?”
summarise() Collapses to a summary “What is our average sale?”

summarise() - collapsing to one number

#>          <int>    <dbl>         <dbl>      <dbl>

n() is a helper that counts rows. It only works inside summarise().

group_by() - the one that makes summarise powerful

A single average across all 1,000 transactions is rarely the interesting number. What you usually want is the average for each branch, or for each product line.

sales |>
  group_by(Branch) |>
  summarise(
    transactions  = n(),
    avg_sale      = mean(Total),
    total_revenue = sum(Total)
  )
#> # A tibble: 3 × 4
#>   Branch transactions avg_sale total_revenue
#>   <chr>         <int>    <dbl>         <dbl>
#> 1 A               340     312.       106200.
#> 2 B               332     320.       106198.
#> 3 C               328     337.       110569.

One row per branch instead of one row overall. group_by() changes nothing about the data - it only tells the next command to work separately within each group.

This is the R equivalent of a PivotTable, and it is the single most useful thing in this notebook.

You can group by more than one column:

sales |>
  group_by(Branch, `Customer type`) |>
  summarise(
    transactions = n(),
    avg_sale     = mean(Total),
    .groups      = "drop"
  )
#> # A tibble: 6 × 4
#>   Branch `Customer type` transactions avg_sale
#>   <chr>  <chr>                  <int>    <dbl>
#> 1 A      Member                   167     321.
#> 2 A      Normal                   173     304.
#> 3 B      Member                   165     325.
#> 4 B      Normal                   167     314.
#> 5 C      Member                   169     337.
#> 6 C      Normal                   159     338.
NoteSelf-check 3

Which product line earns the most total gross income? Write a pipeline using group_by(), summarise() and arrange().

NoteShow the answer 
sales |>
  group_by(`Product line`) |>
  summarise(total_income = sum(`gross income`)) |>
  arrange(desc(total_income))

The order matters. You must group and summarise before you can sort, because the column you are sorting by (total_income) does not exist until summarise() creates it.

A follow-up worth thinking about: the product line with the highest total income is not necessarily the most profitable per sale. Adding mean() of the same column would let you check whether the leader is winning on margin or simply on volume. That distinction is exactly what descriptive statistics exists to expose, and you will meet it again in section 2 of the course.

Putting it together

Here is a realistic question answered with everything above:

Among member customers, which branch has the highest average customer rating, and how many transactions is that average based on?

sales |>
  filter(`Customer type` == "Member") |>
  group_by(Branch) |>
  summarise(
    transactions = n(),
    avg_rating   = mean(Rating)
  ) |>
  arrange(desc(avg_rating))
#> # A tibble: 3 × 3
#>   Branch transactions avg_rating
#>   <chr>         <int>      <dbl>
#> 1 C               169       7.05
#> 2 A               167       7.00
#> 3 B               165       6.77

Four lines, and it reads as English: take the sales, keep members only, group by branch, work out the count and average rating for each, sort best first.

TipWhy the count column is there

An average of 7.2 built from 200 transactions and an average of 7.2 built from 6 transactions are not equally trustworthy.

Reporting a summary statistic without its sample size is one of the most common ways to mislead with data. You will meet the formal version of this idea in section 3.

Summary

You now know:

  • R stores values under names using <-
  • Functions do things and take arguments for extra instructions
  • A data frame is a spreadsheet inside R: one row per thing, one column per measurement
  • read_excel() loads data; glimpse() shows you what you loaded
  • $ pulls out a column, with backticks if the name has a space
  • The pipe |> means “and then”, letting code read like a sentence
  • Five verbs - filter, select, arrange, mutate, summarise - plus group_by() cover most of what you need

That is the entire Fast Intro to R. Later notebooks introduce a handful of new functions each, always with a “New R this week” table at the top, but the foundation does not change.
